# 迁移计划 · deepseek-chat → deepseek-chat-v3

## 1. 背景

- 供应商通知：`deepseek-chat`（v2）2026-11-01 起涨价约 14%，2026-12-31 计划下线。
- v3 评估结果：质量 +0.4，成本 +14%，P95 -15%，通过上线门槛。
- 目标：在 12 月 31 日前完成 40 个试点租户迁移，错误率与成本可控。

## 2. 范围

- 40 个租户（种子数据中的 tenant-001 ~ tenant-040）。
- 不含免费租户中的极端低用量账户（后续批次单独处理）。

## 3. 分批

| 批次 | 覆盖租户 | 策略 | 回滚条件 |
|---|---:|---|---|
| 5% | 2 | 内部/低风险租户，先验证链路 | 错误率 > 2 倍基线 |
| 20% | 6 | 中小付费租户，观察 7 天 | 错误率 > 1.5 倍或 P95 > 1.5 倍 |
| 50% | 12 | 主力付费租户，提前 7 天通知 | 任一 P1 事件 |
| 100% | 20 | 剩余租户，完成下线准备 | 成本超预算 20% |

## 4. 兼容性检查

- [ ] 请求/响应 schema 兼容（OpenAI 格式）
- [ ] 最大上下文：v3 128k，v2 64k；确认租户请求不超过 128k
- [ ] function calling / JSON mode / 流式：逐项验证
- [ ] SDK 版本：确认租户 SDK 不需要升级
- [ ] 计费口径：按新价目表版本计算，账单样例已核对

## 5. 回滚

- 触发：错误率 > 2 倍基线，或 P95 > 1.5 倍基线，或出现 P1。
- 动作：把租户从 `migrations` 标记为 `rolled_back`；网关恢复直连 v2；通知租户。
- 验证：错误率与 P95 回到基线；账单无重复计费。

## 6. 沟通

- T-7 天：邮件/站内信公告，附迁移指南与 FAQ。
- T-1 天：提醒租户检查 SDK 与超时设置。
- T 日：迁移窗口内值班，每小时同步一次状态。
- T+1 天：发送迁移结果与后续支持入口。

## 7. 指标

- 迁移完成率（目标 100%）
- 迁移租户错误率（目标 < 1%）
- 迁移租户 P95（目标 ≤ 基线 1.2 倍）
- 工单量（目标不超过日常 1.5 倍）
- 成本变化（目标 ≤ +15%）
