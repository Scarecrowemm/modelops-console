# 运营 Runbook

> 每类事件都按「检测 → 定级 → 止损 → 根因 → 改进 → 验证 → 关闭」闭环。
> 事件接口：`POST /api/incidents`，关闭：`POST /api/incidents/{id}/close`。

## 1. 429 风暴（rate_limit_storm）

| 项 | 内容 |
|---|---|
| 检测 | 429 占比 > 10%，持续 5 分钟 |
| 级别 | P2；全站 > 30% 或影响付费租户时升 P1 |
| 前 5 分钟 | 看板确认 Top 模型/上游；查供应商状态页；确认是平台限流还是上游限流 |
| 止损 | 把该模型流量切到 fallback；对 Top 租户临时降 RPM；必要时暂停非关键任务 |
| 沟通 | 对受影响租户发公告：现象、影响范围、预计恢复时间、临时方案 |
| 闭环 | 429 占比 < 5% 持续 30 分钟；供应商确认配额；更新路由权重 |
| 复盘 | 为什么会触发？配额预警是否提前？fallback 是否生效？ |

## 2. 上游超时（upstream_timeout）

| 项 | 内容 |
|---|---|
| 检测 | P95 > 2 倍 7 日基线，持续 10 分钟 |
| 级别 | P2；P95 > 5 秒或超时率 > 10% 升 P1 |
| 前 5 分钟 | 区分单模型/单上游/全站；看 DNS、TLS、出口网络；看供应商状态 |
| 止损 | 切备用上游；降低超时阈值；暂停长上下文任务 |
| 沟通 | 告知租户延迟上升与重试策略，避免客户端雪崩 |
| 闭环 | P95 回到基线 1.2 倍以内；连续 1 小时无超时 |
| 复盘 | 超时阈值是否合理？重试是否放大流量？ |

## 3. 成本突增（cost_spike）

| 项 | 内容 |
|---|---|
| 检测 | 日成本环比 > 20%，或单位请求成本 > 1.5 倍 |
| 级别 | P3；单日成本 > 预算 2 倍升 P2 |
| 前 5 分钟 | 按模型/租户/请求长度拆解；核对价目表版本是否切换 |
| 止损 | 对异常租户设置预算提醒/临时限流；确认不是价格变更导致 |
| 沟通 | 给 Top 租户发用量提醒；必要时提供优化建议 |
| 闭环 | 定位到具体租户/模型；成本回到预期区间；账单核对完成 |
| 复盘 | 为什么没有提前预警？预算阈值是否合理？ |

## 4. 模型质量回退（quality_regression）

| 项 | 内容 |
|---|---|
| 检测 | 评测通过率环比下降 > 5 个百分点，或客户投诉集中 |
| 级别 | P2；核心租户受影响升 P1 |
| 前 5 分钟 | 复跑评测集；对比版本/供应商变更记录；抽样人工复核 |
| 止损 | 回滚到上一版本；切备用模型；暂停自动升级 |
| 沟通 | 告知租户问题与回滚计划 |
| 闭环 | 复跑通过率恢复；供应商确认原因；模型卡更新 |
| 复盘 | 评测集是否覆盖该场景？为什么没提前发现？ |

## 5. 密钥泄露（key_leak）

| 项 | 内容 |
|---|---|
| 检测 | 单 Key 调用量突增 / 异地 IP / 异常模型组合 |
| 级别 | P1 |
| 前 5 分钟 | 立即吊销 Key；确认泄露来源（仓库/日志/客户端） |
| 止损 | 轮换 Key；限制租户；排查异常调用并保留证据 |
| 沟通 | 通知租户安全事件与轮换步骤 |
| 闭环 | 旧 Key 无调用；新 Key 正常；泄露源已修复 |
| 复盘 | 密钥管理流程是否缺失？是否需要接入 Secret 扫描？ |
